# Legacy Instruction Preservation Audit

This audit compares the absorbed packages' archived `SKILL.md` and linked Markdown references in the [skills archive at `ad7205f`](https://github.com/polaralias/skills/tree/ad7205f7591bd53c2addaba4536bda6b2aec0ab6/archive) with the current EWF package. It classifies useful instructions by owner. **Outcome parity** is separately evidenced in RKE's legacy parity matrix; a passing operation test does not prove that editorial guidance survived. A historical instruction is not automatically current authority.

| Source | Agent judgement and output expectations retained in EWF Markdown | Deterministic mechanics owned by a command | Deliberate omission or other authoritative owner |
| --- | --- | --- | --- |
| EWO, `engineering-workflow-orchestrator` and hook references | [Workflow contract](workflow-contract.md), [continuity](continuity.md): proportionate phase choice, gate ownership, host-conditional transcript → max handoff → supplement → manifest → verified pickup. | RKE owns `activate`, `checkpoint`, `resume`, `close` and thin hooks; a verified host integration owns transcript backup and manifest file plumbing where supported. | Old peer-skill stage labels and bundled Claude helper are not a second live lifecycle. No host-specific compaction support is asserted without current host verification. |
| RDS, `repo-dissection` | [Understand journey](journeys/understand.md): declared versus actual source/package/runtime path, public-boundary probes, mismatch classification and a minimum trustworthy foundation. | `dissection assess`, bounded retrieval and structure operations. | Old standalone skill routing and Python inventory are superseded. A declared launcher is not automatically executed or treated as verified. |
| QTK, `query-to-knowledge` | [QTK extension](extensions/query-to-knowledge.md): coherent question batches, owner decisions, concrete scenario tests, recommendations, durable synthesis and stop conditions. | Capability and `shared-understanding` gate transitions. | A separate QTK workflow state and broad questioning ritual are unnecessary; source text cannot supply user authority. |
| RKE, `repo-knowledge-engineering` and OKF profile | [Knowledge methodology](knowledge-methodology.md) plus [knowledge contract](knowledge-contract.md): glossary and decision placement, optional authority/verification/navigation fields, decision supersession, contradictions, retrieval and retain/merge/archive/delete judgement. | `knowledge check`, `build-indexes`, `register`, `context verify`, `documentation apply` and source-identity checks. | Archived Python bundle tools and task schema are superseded. Optional editorial fields are not represented as hard RKE validator checks; Task and task-visualisation mechanics belong to OKF Tasks. |
| DDD, `doc-driven-development` | [Design journey](journeys/design.md): feature contracts, scenario pressure tests, observable acceptance, proportionate technical plan, work packages and traceability. | Journey and gate state; downstream task creation through OKF Tasks if justified. | Exact old artefact filenames and an always-on separate QA-plan route are omitted; standalone human QA plans remain outside EWF. |
| RTL, `repo-task-lifecycle` | [OKF Tasks adapter](okf-tasks-adapter.md): proposed/ready judgement, required workstreams, honest effort and evidence axes, final promotion and tracker destination review. | Authoritative OKF Tasks CLI for record creation, time, strict validation, profiles, provider sync and readback; RKE only selects mode and checks the lane. | Archived YAML schema, provider recipes and `(system, id)` external bindings are not live EWF instructions. The current OKF Tasks specification and CLI own them. |
| WTC, `worktree-task-coordinator` | [Parallel delivery](extensions/parallel-delivery.md): isolation justification, single-writer ownership, dependency order, integrated-tree validation, exact-tip cleanup and separate external authority. | `coordination validate`, `plan`, `cleanup-check` and explicitly authorised `cleanup`. | Archived Python manifest implementation and provider-specific PR assumptions are omitted. A merged PR label alone is not cleanup proof. |

Large logs, secrets and duplicate canonical records are omitted. |
| LPK, `local-pickup` | [Continuity](continuity.md): manifest-first recovery where available, active selection, per-claim re-verification, drift classification and a current-state restart decision. | `handoff inspect`, `resume` and current Git/knowledge/task checks. | Superseded or stale notes cannot grant an action; missing artefacts route to rediscovery. |
| RPF, `repo-publish-finaliser` | [Publication review](publication-review.md) plus [extension](extensions/publication.md): implementation/public-doc agreement, a bounded safety sweep, archive disposition and release-profile choice. | `publication scan`, project CI and release validators; separate `repo-setup` profile assets own starter automation. | The archived workflow YAML and automatic scanner installation are omitted. A clean scan is not publication approval. |
| TPU, `tracker-publisher` | [Tracker publication adapter](tracker-publication.md): preserve accepted hierarchy and acceptance, choose preview or scoped live publication, verify destination and report actual provider results. | `tracker preview` for non-OKF packages; OKF Tasks profile and provider CLI for durable records. | No EWF-owned provider client or invented local Task ledger. A preview is not a write. |

`repo-setup` remains separate pre-workflow bootstrap. `test-plan-writer` remains outside EWF for a standalone human QA-plan request. Neither is an absorbed parity row. The archive remains historical evidence; future instruction changes belong in these live references or the owning independent specification, not in copied legacy packages.
