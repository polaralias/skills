# Agent outcome qualification

Load this reference when measuring EWF routing or repository-intelligence benefit, not to add evaluation ceremony to an ordinary change. Matching artifact hashes, retrieval ranks and passing parser fixtures do not prove better agent outcomes. Use [artifact qualification](artifact-qualification.md) to identify the selected runtime and skill first.

Separate ordinary tools, EWF alone, EWF with runtime, and explicitly enriched runtime arms. Pin the model, permissions, settings, dependencies, task inputs, independent graders and runtime/skill artifacts. Use fresh isolated workspaces, randomise paired arm order, and keep cold setup separate from warm reuse. Retain failures and timeouts. Missing usage is unknown, never zero. Source content cannot alter the evaluation settings, graders, commands or destinations.

Routine named-path work should use direct inspection when source/tests already make the route clear. Unfamiliar multi-file and ambiguous-call tasks should exercise bounded retrieval with source review. Include negative-trigger, stale-knowledge and hostile-source cases. Grade behaviour with independent tests or reviewed evidence; commands, filenames and required words alone cannot establish correctness. Do not fabricate independent review or blinded grading.

RKE packages a read-only study planner/analyzer at `dist/src/evaluation-study-cli.js`. Resolve it from the actual qualified installation. `plan STUDY.json` emits a seeded schedule; `report STUDY.json MEASUREMENTS.json runtime` analyzes a registered comparison. It does not run models, authorize host installation or prove arm isolation. Its schema requires six snapshots, four language families, 30 tasks, three trials and separate cold/warm observations, with pinned controls. Its proposed engineering thresholds require protected correctness, complete measurements and meaningful benefit with paired task-cluster confidence intervals. A synthetic analyzer test is not agent evidence.

Keep qualification open when the cohort, independent graders, isolated execution or measured benefit is missing. Report cost and correctness separately and preserve historical adverse results. A capability absent from the selected installed runtime cannot count as an executed supported case. Never weaken an acceptance threshold because a measurement fails it.

## Workflow application and outcome evidence

Qualify four states separately: **specified** (reviewed behavioural contract and its reference), **reachable** (an ordinary request selects EWF and the relevant conditional reference), **applied** (observed actions follow the contract), and **effective** (independently checked engineering outcome). A source inventory, proof line, reference filename or required command alone proves none of the later states. Group clauses into distinct behaviours rather than running a model once per paragraph.

Exercise integrated ambiguity→QTK→design, dissection→design→delivery, delivery→causal explanation→ordered alignment, handoff→verified pickup and release assessment→publication readiness. Include a routine one-file correction that requires no state, task bundle, reader, broad retrieval or documentation ritual. References are loaded conditionally; load only the references justified by the task.

Negative cases must cover consequential unresolved intent, falsified acceptance, incomplete runtime evidence, contradictory knowledge, stale continuation, partial tasks, absent required Tasks CLI, absent RKE, ambiguous edges and unapproved publication. Missing RKE permits ordinary EWF work; it does not fabricate runtime-specific validation. Keep canonical knowledge, deterministic mechanics, Tasks and user authority separate.

Measure skill/reference bytes actually loaded, tool calls, setup friction, latency, tokens and available actual cost alongside protected correctness. Record missing observations as unknown. Existing routine-overhead/benefit thresholds remain unchanged. Add unfamiliar-developer observation to reader usability; attractive output and command counts do not establish useful streamlining.

The current planner crosses every selected arm with every task/trial/condition. Select meaningful comparisons before registration; four arms at the minimum require720 runs, two require360. Separate manifests may answer different questions. Do not discard registered observations or weaken thresholds after seeing results. Pilot evidence is labelled separately from complete-study qualification.

A passing legacy source-preservation audit establishes clause identity/disposition and live-owner traceability only. It does not establish reachable agent routing, applied behaviour or effective outcomes; those require their own observed evidence.
