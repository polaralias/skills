# Runtime capabilities and EWF compatibility

EWF is the user-facing engineering router. Its references own reasoning and outcomes; this skill supplies optional runtime mechanics. Former names below identify the methods now consolidated into EWF, not instructions to load archived packages. Legacy RKE means Repository Knowledge Engineering; the current RKE runtime is a separate product.

| Runtime facility | EWF method and former skill | Relationship and activation boundary |
| --- | --- | --- |
| SQLite FTS5/BM25 retrieval, bounded excerpts and context benchmarks | Comprehension / RCC; dissection / RDS; clarification / QTK; delivery; knowledge / legacy RKE | Finds evidence candidates for the selected question. Read consequential source; ranking and recall do not establish truth. [Context contract](repo-context-contract.md). |
| Code APIs, traces, maps, changed-symbol impact and structural search | Comprehension / RCC; dissection / RDS; delivery; design / DDD | Helps locate definitions, callers and affected surfaces. Parser coverage and unresolved edges remain visible. [Structural context](structural-context.md). |
| Trusted language-server resolution and digest-bound agent code reviews | Comprehension / RCC; dissection / RDS; delivery | Optional deeper navigation when parser evidence is insufficient. Profiles are host-controlled; an agent review remains inference. [Structural context](structural-context.md) and [language-server profiles](language-server-profiles.md). |
| Documentation bootstrap and ordinary material-change discovery | Dissection / RDS; delivery; knowledge / legacy RKE; alignment / RSA | Bootstrap inventories a requested foundation. Assessment combines explicit bindings with bounded lexical candidates for the final change; review and authorship remain methodological. Assessment is conditional on useful evidence or repository policy and needs no workflow state. [Documentation lifecycle](documentation-lifecycle.md). |
| OKF frontmatter walking, bundle/graph checks, generated indexes, explicit bindings and source freshness | Knowledge / legacy RKE; clarification / QTK; alignment / RSA | Checks adopted format, relationships, findability and byte identity. These checks support canonical authoring without proving factual correctness. [Knowledge contract](knowledge-contract.md) and [OKF profile](okf-profile.md). |
| Documentation apply/disposition receipts and configured close/pre-push checks | Delivery; knowledge / legacy RKE; alignment / RSA | Records reviewed change evidence and enforces configured requirements. Candidates require review, not mandatory edits. Receipt-free bounded review remains available unless policy requires receipts. [Documentation lifecycle](documentation-lifecycle.md). |
| Persistent phases, journeys, capabilities, gates and checkpoints | Design / DDD; delivery; alignment / RSA; EWO shared orchestration | Optional memory and mechanical obligation tracking for longer work. Not a second methodology or a prerequisite for retrieval, edits or documentation review. [Workflow support](workflow-support.md). |
| Independent OKF Tasks modes, validation and tracker/provider integration | Task lifecycle / RTL; design / DDD; alignment / RSA; publication / TPU | Authoritative task producer owns records, execution status, schema and providers. RKE delegates; EWF decides accepted work and evidence. [OKF Tasks adapter](okf-tasks-adapter.md). |
| Checkpoint, local/shared handoff writing, standard/max depth, supersession and pickup selection | Handoff / LHO, including LHO max; pickup / LPK; EWO continuity | Preserves unfinished work and selects continuation evidence. Reverify claims and authority before acting; host compaction support has explicit limits. [Continuity](continuity.md). |
| Parallel ownership manifests, worktree plans and exact-tip cleanup | Coordination / WTC; delivery; alignment / RSA | Supports authorised parallel work, integrated validation and narrowly authorised cleanup. Planning and eligibility do not allocate or delete worktrees. [Coordination](coordination.md). |
| Hygiene scans, public-readiness evidence, accepted-package tracker previews | Publication / RPF and TPU; task lifecycle / RTL | Supports readiness and publication mapping. Scans are bounded; preview neither publishes nor grants permission. [Publication support](publication-support.md) and [tracker publication](tracker-publication.md). |
| Multi-repository evidence federation | Comprehension / RCC; dissection / RDS; clarification / QTK; design / DDD | An explicitly selected extension of bounded investigation across caller-authorised roots. It creates no cross-repository authority or canonical truth. [Workspace federation](workspace-federation.md). |
| Prepared, validated and cached subsystem explanations | Comprehension / RCC; dissection / RDS | Explicit reusable derived explanation support. Ordinary explanations still use source directly; cache validation does not certify inferred semantics. [Derived explanations](derived-explanations.md). |
| Reader projections, graph/diagram visualisation, offline export and fixed-root live reading | Knowledge / legacy RKE; comprehension / RCC; dissection / RDS | Explicit presentation of selected evidence. Derived views retain provenance and coverage limits; they do not replace canonical docs. [Reader workspace](reader-workspace.md). |
| CLI/MCP host integration, install/inspect/repair/remove and optional hooks | Selected EWF method for the engineering task; no former specialist equivalent for host administration | Runtime administration is a separate explicit request or authorised setup need. Installing tooling is not part of ordinary delivery by default. [Host integration](host-integration.md). |
| Runtime/package/skill identity qualification and agent evaluation | Delivery and publication / RPF for release evidence; no former specialist equivalent for runtime attestation | Distinguishes shipped bytes, loaded process, selected skill and measured agent outcomes. Packaging checks do not establish live adoption or practical benefit. [Artifact qualification](artifact-qualification.md) and [agent evaluation](agent-evaluation.md). |

For the ordinary coding path, select delivery, inspect and change the relevant source, assess explicit and candidate documentation impact, review and update only warranted claims, then verify and report. Broader facilities are conditional extensions of that path, not prerequisites to it.
