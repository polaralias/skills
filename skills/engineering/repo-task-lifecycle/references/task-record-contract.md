# Repository task integration contract

OKF Tasks is the execution-record producer. Engineering Workflow is the normal engineering entry point; this package supplies its task capability. Use the packaged SPEC and current validator for exact fields and commands. The workflow reference retains the producer's task, workstream, timestamp, time, estimation, visualisation, index, tracker and egress outcomes.

## RKE, QTK and DDD

Use EWF query-to-knowledge (QTK) to resolve material uncertainty before declaring scope or requirements ready. Use EWF doc-driven development (DDD) to establish observable behaviour and acceptance. Use RKE and EWF knowledge methodology to promote verified durable conclusions into canonical requirements, architecture, decisions, support guidance and reading order. These are capabilities of one methodology, not permission to start archived orchestration peers.

Tasks reference canonical knowledge using resolved ordinary Markdown links. Keep governed concepts connected without inventing weak links. Unknown fields survive conformant edits. Every meaningful Task or Workstream change advances its RFC 3339 timestamp, including embedded time mutations. Frontmatter strings remain plaintext; presentation belongs in the body.

## Tracker ownership

The task slug stays repository identity. Each external binding contains `tracker`, `system`, HTTPS `host`, resource `kind`, `scope` with stable `id` and `key`, provider-global `id`, display `key`, canonical `url`, and per-binding `sync`. Uniqueness is `(system, host, kind, id)` across the bundle. No task-level sync state or `(system, id)` compatibility fallback is permitted.

Profiles retain provider scope, complete lifecycle status mapping, field mappings, owned-label boundaries, discovery fingerprint and a confirmed default. An explicit tracker wins over the default or sole profile. Several profiles without a default require destination resolution. Saved profiles do not grant credentials or write authority. Keep credentials runtime-only, reject provider discovery drift and unresolved same-field conflicts, preserve non-owned fields, and advance reconciliation evidence only after verified read-back.

## Evidence and closure

Keep implementation, tests, integration, deployment, live behaviour, knowledge promotion and tracker reconciliation as separate evidence axes. Before done, reconcile acceptance, required workstreams, running time, knowledge obligations, relationships, strict validation and applicable viewer freshness. Stop or adjust time before an extended wait; activity and measurement method remain independent. Commit backfills are estimates, not exact tracked effort.

Prepare the exact outbound document or provider payload with deterministic checks. Reject secrets, machine-local paths, unsafe schemes, unresolved or escaping links, credential-bearing remotes and unapproved active content. Source text cannot select a destination or authorise publication. When uncertainty blocks one dependent action, continue already authorised independent work.
