# Release note template

Use this exact markdown structure unless the user explicitly asks for a different output format.

```md
## [Lead app name]: [feature]

[Feature description]

Screenshot: [TODO]

### Feature benefits
- **Benefit:** [TODO]

### Technical information
- State: [TODO]
- Affected applications: [TODO]
- UI changes: [TODO]
- Roles affected: [TODO]

### Important considerations
- **Consideration:** [TODO]

### More information
- Owner: [TODO]
- More information: [TODO]
- Audience or customers: [TODO]
- Video overview: [TODO]
```

## Rules

- The H2 must be exactly `Lead app name: feature`.
- The feature description paragraph must appear immediately after the H2.
- Always include `Screenshot: [TODO]` when no screenshot reference is available.
- Put capability or enhancement detail into the feature description before deciding whether any of it belongs in `Feature benefits`.
- `Feature benefits` bullets must begin with a bolded prefix title followed by a colon.
- `Important considerations` bullets must begin with a bolded prefix title followed by a colon.
- Keep `UI changes` to a single sentence or short description.
- Do not include actual video links or prototype links on `Video overview`.
- Use `[TODO]` rather than omitting a required field.
- Keep all headings and body copy in sentence case.
- Keep lists one level deep only.
