# Query To Knowledge Checklist

- read code and canonical docs before asking questions
- separate repo-answerable questions from user-judgment questions
- batch 2 to 5 tightly related questions by theme
- keep each question short
- use concrete scenarios to force precision
- summarize resolved, open, and changed understanding after each batch
- capture resolved terms in `GLOSSARY.md`
- capture durable decisions in `docs/decisions/`
- hand off to repository-knowledge-engineering when the main job becomes broad knowledge-base maintenance
